## 当前实现

- 当前代码保留六十日十九事件、五条人生方向、序章三种可接续暂结、十条端到端通关样本，以及关系记忆、经济、三账、成长、战斗、地图、存档等原系统。P2-1 将另行把固定终局日改为有限条件窗口，不属于本记录所述已完成交付。
- 九张立绘使用构建基路径，换角色重新建立资源加载状态。根站和项目子路径共用资源登记；未知角色或图片失败有明确文字占位。
- 八幅原创代码绘制水墨 SVG 覆盖荒道、城门、客栈、医馆、码头、盐仓、县衙、破庙。开场、地点、终局同步更新图与地点说明；窄屏保留环境文字。资源失败不影响对话和选项。
- 本地桌面 `/` 正确映射实际 HTML 入口；Pages 项目内地图采用片段导航，返回不跳离项目目录。未修改已发布网站。
- 战斗失物文案使用中文材料名；玩家界面不展示内部材料键、NPC 战斗等级、资格判断或零变化字段。当前只接纳 v7 存档，不对 v1—v6 做显示迁移。
- 唯一详细分支图登记十九事件和九类特殊场景，包括城门、客栈、医馆、证物、关系、序章暂结及三类人生终局。审查准入检查模板、反馈文案和实际信息来源，新增分支未登记将触发测试失败。
- 三类核心证明各有三个独立场景来源，并实际执行取证与存读。序章尸体实名属于可选封存分支的局部核验，未将其误报为全篇三路径强制门槛。
- 背包只显示实际持有物和证据，包含概览、已知来源、用途及当前不可用原因。使用需再次确认，复用当前有限选项和裁决，不恢复被扣押、交存或遗失的实物。
- 下一步引导只在对话读完且眼前没有有效探索时显示，按伤势、现场变化和已知去处排序，至多两条，不代选路线。地图、日志及已知人物/地点保留可回查方向。
- 城门首次盘查不再提供沉默或无依据放行。现实通路包括说明来历后登记候验、核验已有文书、主动交验残片并复核、退开找筹码，以及先观察暗示再实付两两的私下通融。
- 第一日新增三条独立牵引入口：行囊辨认痕迹、守门差役听见编号后的异常反应、客栈提前问话。跨入第二日只结算一次主动归纳或较弱保底，提示人、船或落脚处将变化，不设置立即失败。
- 人物详情与已知人物页显示关系阶段，不显示五维数值；仅跨阶段时出现一次非数值反馈。十九事件的姓名在自报、名帖、点名或旁人称呼后同步，未知姓名在当前对话、历史和日志中继续按观察称呼投影。
- 修复打听消息期间死亡后仍把未听到的事件标为已知的问题；死亡即停止消息接收。
- 渡口“试探此地近况”现可结算出盐路与船货的具体观察；渡口、客栈、医馆及通用探索／打听入口均在取得结果后隐藏，条件不足时提供明确不可用原因，不再保留可见却无反馈的按钮。
- 行动区按同一游玩会话中实际最大可见选项数保留高度；列数只在 `sm` 屏幕断点变化。低风险、无即时重大代价的观察／打听收纳到二级选择，时间、立场、高风险和关键行动仍直接显示。运行时玩家文案已移除“定稿”、验收、开发阶段等内部词语。
- 第一天结束前只建立“有人关注主角”的悬念；第二天通过官面告示把异常指向盐路、渡口及县城秩序；第三天由县衙告示、渡口旗号与脚夫秩序、青岳门名帖和门人三个不同视角，说明三方公开身份、表面冲突及主角因残片与带伤行囊被卷入的原因，不提前归属罪责、暗中交易、背叛或幕后责任。
- 序章至第 60 日会改变剧情、地点、时间、资源、关系或证物的行动均已按场景审计；隐藏、拒绝、候验与条件回应由当下状态、在场人物、玩家已知和 NPC 身份共同裁决，伪造不可见行动不写状态。
- 城门未获实际放行时不显示客栈或医馆问路，也不解锁地点或服务；放行或复核放行后才开放。扣留时只保留搜查、陈述和复核路径，释放与继续主线没有死锁。
- 序章至第 8 日的剧情、旁白、对白、行动标题与提示、札记、背包说明、场景引导和日志已统一改写。第一幕按亲见、耳闻与可信来信逐步展开，不让旁白替玩家断定尚未发生的事。
- 第 4—8 日五个事件各有可观察前兆或来信、自然抵达、可选查探或准备、到场取舍及事后痕迹。事件仍会自行发生；主动行动只改变既有边界内的信息、资源、现场损失和人物处境。
- 第 7 日起火前只呈现靠近木账房的油罐、见底水缸、东风和换岗空缺。玩家可花三两与四十五分钟补水、移油并备破窗钩和疏散绳；火仍会发生，布置只改变现场损失与救援处境。起火或取得物证后，文本才使用“纵火”。
- 第 20 日城门查探只核路牌、公开告示、近三日来往簿、脚程与路况；没有把半个时辰写成已经与两日外路上的药农、船户或递状人分别问话。三条外路、两日往返和全部既有结算保持不变。
- 第 49 日“一船黑水”的前兆与现场只以船体进水、药桶、取水口、脚夫和船货建立风险；已删去无行动承接的点火、纵火及火把表述，没有新增补救路径或改变船难结算。
- 第 41 日及同类玩家可见文本改用人物、物件、动作和当场后果交代边界；内部审查表、测试术语与合理语义未作机械删除，NPC 知识、关系、证据和事件结果不变。
- 关键选择小字改为逐项显式文案，只在本次会立刻改变银两、伤势、真气、追查、证物、人物处境或眼前取舍时显示；离场、越过时限和按效果自动拼接的统一兜底已取消，无即时变化的入口不显示小字。
- 第 4、7、20、32、57 日查探分别补足后墙守位、真实防火准备、城门公开核对、河战三处取舍和证人夜三路守位的独立决策视角；其余十四项查探不删除、不新增，也不在本轮重新判定必要性。
- 第 9—60 日十四个后期既有事件保留自然来源、主动查探、错过补知与事后回声；十九事件到场标题、逐项关键选择小字和玩家可见结果采用自然叙事。听审减免须确有水道经历，最后报价减免须确有追查；第二日委托只由现场苏晚棠回应。
- 全篇冲突采用三层信息：自然行动标题、当场目标与放弃项、会改变本次结算的战况或代价。无变化的生命、真气和银两不显示；付资脱身只列实付银两与放弃项；交械投降明确进入拘押结局。
- GameState 为 v7；v1—v6、缺字段、旧结果和伪造结果均拒绝，不迁移、不补默认值。浏览器与桌面端各在首次运行 v7 时一次性清理旧 v5 自动档、备份和手动档，写入完成标记并显示规定失效提示。
- 见闻札记仅投影玩家亲见／取得的事实、他人说法和待解疑问；不会展示事件隐藏摘要、幕后结论或正确选项。
- 唯一详细分支图和内部审查表已逐项登记全部十九事件的推动者与动机、触发条件、玩家当下已知、缺席结果、前兆、三层不同来源、事后回声、可变后果、存档影响和测试点。
- P0-8 提供名称为《青石江湖》的 Web App Manifest、Android 192／512／maskable 图标和 iOS 180×180 `apple-touch-icon`，以 `standalone` 独立窗口打开。资源使用相对 Manifest 地址和 Vite `BASE_URL`，兼容根路径与 `/qingshi-jianghu/`。
- 没有 Service Worker 或离线缓存策略。主屏模式未读到存档时，会在“新的旅程”操作前提示浏览器与主屏入口可能存在存储隔离；首次玩家仍可明确选择正常开始。

## 存档策略

GameState 为 v7，浏览器存储键前缀为 `qingshi-jianghu-save-v7`（自动档键为 `qingshi-jianghu-save-v7:auto`），桌面数据库为 `qingshi-jianghu-v7.db`。按钮风险提示、行动说明与冲突预览只由当前状态派生，不写入存档。

解码器只接受字段完整、枚举合法、数值与交叉状态一致、事件结果符合当前分支的 v7；v1—v6、缺失字段、旧结果和伪造结果一律拒绝，不执行迁移或默认值填充。首次运行 v7 时，浏览器清除所有旧 `qingshi-jianghu-save-v5` 自动档、独立备份、手动档和元数据；桌面端清空旧 `qingshi-jianghu-v5.db` 中的 `saves` 与 `save_backups`。两端均在 v7 位置写一次性完成标记，后续启动不重复清理，也不删除当前 v7 档。首次清理后、开始新游戏前显示：`剧情规则已更新，旧存档已失效，请重新开局。`

当前 v7 自动主档损坏时仍可回退同版本有效备份。已结算事件不会因读取、渲染、进出场景或备份回退而重演、补发奖励或推进时间。
