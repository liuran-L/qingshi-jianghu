# 青石江湖实施与验收总记录

更新：2026-09-08。仅记录当前版本结论。P0 试玩前剧情、引导与反馈回补已完成本地技术实现与自动化验收；三类真人试玩尚未执行，不记为通过。P2 未开始。本轮没有提交、推送或发布。

## 当前实现

- 保留六十日十九事件、五条人生方向、序章三种可接续暂结、十条端到端通关样本，以及关系记忆、经济、三账、成长、战斗、地图、存档等原系统。
- 九张立绘使用构建基路径，换角色重新建立资源加载状态。根站和项目子路径共用资源登记；未知角色或图片失败有明确文字占位。
- 八幅原创代码绘制水墨 SVG 覆盖荒道、城门、客栈、医馆、码头、盐仓、县衙、破庙。开场、地点、终局同步更新图与地点说明；窄屏保留环境文字。资源失败不影响对话和选项。
- 本地桌面 `/` 正确映射实际 HTML 入口；Pages 项目内地图采用片段导航，返回不跳离项目目录。未修改已发布网站。
- 战斗失物文案使用中文材料名。旧档表达中的英文材料、来源等仅由显示投影转换，原始历史和内部兼容标识保留。这里验收的是玩家可见内容；不宣称 v6 内部键已从程序包中删除。
- 唯一详细分支图登记十九事件和九类特殊场景，包括城门、客栈、医馆、证物、关系、序章暂结及三类人生终局。审查准入检查模板、反馈文案和实际信息来源，新增分支未登记将触发测试失败。
- 三类核心证明各有三个独立场景来源，并实际执行取证与存读。序章尸体实名属于可选封存分支的局部核验，未将其误报为全篇三路径强制门槛。
- 背包只显示实际持有物和证据，包含概览、已知来源、用途及当前不可用原因。使用需再次确认，复用当前有限选项和裁决，不恢复被扣押、交存或遗失的实物。
- 下一步引导只在对话读完且眼前没有有效探索时显示，按伤势、现场变化和已知去处排序，至多两条，不代选路线。地图、日志及已知人物/地点保留可回查方向。
- 城门首次盘查不再提供沉默或无依据放行。现实通路包括说明来历后登记候验、核验已有文书、主动交验残片并复核、退开找筹码，以及先观察暗示再实付两两的私下通融。
- 第一日新增三条独立牵引入口：行囊辨认痕迹、守门差役听见编号后的异常反应、客栈提前问话。跨入第二日只结算一次主动归纳或较弱保底，提示人、船或落脚处将变化，不设置立即失败。
- 人物详情与已知人物页显示关系阶段，不显示五维数值；仅跨阶段时出现一次非数值反馈。十九事件的姓名在自报、名帖、点名或旁人称呼后同步，未知姓名在当前对话、历史和日志中继续按观察称呼投影。
- 修复打听消息期间死亡后仍把未听到的事件标为已知的问题；死亡即停止消息接收。

## 存档策略

GameState 仍为 v6，存储键仍为 `qingshi-jianghu-save-v5`。本轮没有新增必填字段、账本或迁移脚本；首日牵引只增加四个合法 `playerKnownFactIds` 枚举值，旧档缺省即未知。关系阶段、场景引导和阶段变化提示均为显示投影或页面瞬时状态。合法 v5/v6 继续经原解码器读取；读档不补发姓名/线索、不推进时间、不重放阶段提示，已经进入长篇的旧档也不会迟到补发第一夜传闻。原有伪造、矛盾、部分字段缺失及备份回退测试全部保留并通过。

## 验收边界与后续

用户已选择“稍后试玩，先完成技术验收”。没有真人首次游玩结论；没有真实浏览器鼠标点击、屏幕阅读器、浏览器像素级截图或原生 Tauri 包/SQLite 实机验收。图像失败和切换由组件实际回调及静态渲染测试验证，导航与资源另有路径和 HTTP 验证，不把它们称为真机视觉验收。

稍后真人应由三类玩家各自无讲解试玩 30—60 分钟，核对：首次能否理解下一步、看到角色与场景、理解物品用途、感知关系阶段与 NPC 后果、错过主动调查后仍获得继续动机，以及遗漏可选互动仍能继续。反馈前不扩展 P2。

仍需需求负责人单项确认的剧情疑点：第一幕“提前知道主角会来”的来源究竟落在现有三方中的哪一方，以及对方想确认的目标物是否就是丁字十七残片。当前实现按要求只建立悬念，不锁定嫌疑人、不改写既有三方动机；未来揭露前必须先确认。仍有约 555 kB 桌面主包大小提示、vinext 路由静态分类提示和本机 npm `python` 配置提示，均不是构建失败。

复现资源验证：先运行完整检查，再执行 `npm run desktop:build -- --base=/qingshi-jianghu/ --outDir dist-pages-preview` 和 `node tools/check-resource-builds.mjs`。本轮到此停止，不提交、不推送、不发布。
