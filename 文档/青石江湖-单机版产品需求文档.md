## 2. 产品定义

《青石江湖》是一款低魔、高风险、高自由度的单机文字武侠角色扮演游戏。

接入大模型后，玩家可通过自由输入与人物、场景和物品交互；未接入或 AI 不可用时，游戏隐藏自由输入框，改为显示由本地规则根据当前情境生成的有限选项。大模型负责理解自然语言、生成符合人物性格的表达；本地规则引擎始终负责决定行为是否合法、信息是否可知、事件是否发生、数值如何变化以及角色是否死亡。

游戏世界不会等待玩家接取任务。青石县的势力会依据世界时间、掌握的证据和彼此关系自行行动。玩家可以参与、旁观、欺骗、交易、站队或尝试离开，并承担连续后果。

## 3. 业务目标

### 3.1 Demo 目标

1. 证明自由输入与严格规则能够同时成立。
2. 证明 NPC 可以自然对话，但不会越过知识边界或替玩家推进剧情。
3. 证明固定事件可在玩家不参与时继续发展，并根据玩家行为改变结果。
4. 证明游戏能够以 Windows 单机程序运行，本地保存完整进度。
5. 允许少量测试玩家使用自己的 API Key 体验 AI 对话。
6. AI 断开后仍保留一个完整、可恢复且不会损坏存档的游戏状态。
7. 证明第一、二日仅凭对话、观察和有限行动，也能形成多条有连续回声的可玩路线。

### 3.2 成功标准

- 测试玩家无需启动开发环境即可安装并进入游戏。
- AI 可用时，玩家可以在不使用固定对话选项的情况下完成开场盘查、调查和地点发现；AI 不可用时可用情境选项完成同一流程。
- 同一 NPC 对明显不同的表达产生不同反应，且反应符合身份与性格。
- 玩家不能通过一句话凭空创造身份、物品、关系或世界事实。
- 玩家可在本地保存、退出并恢复进度。
- API 失败不会造成卡死、状态重复写入或存档损坏。
- 八日世界事件能够按时间触发，不依赖任务领取。
- 第一、二日单条路线包含 8—12 次有意义的决策，完整体验约 40—60 分钟，并能形成至少 3 种明显不同的两日结果。
- NPC 会记住玩家的具体说法、拒绝、承诺和矛盾；重复追问不会无限获得相同回复或收益。

## 4. 目标用户

### 4.1 首期用户

- 喜欢武侠、文字冒险、沉浸式角色扮演的玩家。
- 能够按照说明申请或填写大模型 API Key 的测试玩家。
- 接受 Demo 内容规模、文字为主表现形式和不稳定 AI 响应的玩家。

### 4.2 非目标用户

- 期待多人联机、竞技排行或合作副本的玩家。
- 期待大量动画战斗、3D开放世界或即时动作操作的玩家。
- 完全不愿配置 API，又要求无限自由对话的普通商业用户。
- 需要手机、主机或 macOS 原生版本的玩家。

## 5. 核心业务场景

### BS-01：首次安装与启动

**前置条件**：玩家使用 Windows 10/11 x64。  
**主流程**：

1. 玩家安装或解压游戏。
2. 游戏建立本地数据目录与默认设置。
3. 游戏显示“新游戏、读取存档、设置、退出”。
4. 未配置 AI 时，玩家仍可开始游戏；界面明确说明当前使用有限对话模式。

**结果**：玩家无需账号即可进入游戏。

### BS-02：配置 AI

**前置条件**：玩家拥有兼容供应商的 API Key。  
**主流程**：

1. 玩家进入设置。
2. 填写服务地址、模型名称与 API Key。
3. 点击“测试连接”。
4. 游戏显示连接成功、鉴权失败、余额不足、限流、超时或模型不可用。
5. 成功后保存配置；API Key 不写入普通存档和日志。

**异常流程**：连接失败时保留已有设置，允许进入有限对话模式。

### BS-03：创建角色并进入开场

1. 玩家填写姓名或使用默认称呼。
2. 玩家选择一个受规则约束的基础出身，或使用系统随机出身。
3. 游戏根据出身分配初始能力、已知常识与一个明确弱点。
4. 主角在荒道袭击后醒来，轻伤、疲劳、路引遗失。
5. 玩家抵达青石县城门，进入马三刀盘查。

**边界**：玩家可自由描述过去，但描述只属于“玩家主张”，不能覆盖已确定背景。

### BS-04：自由输入与 NPC 对话

**前置条件**：玩家已成功配置并启用大模型。  

1. 玩家选择对话对象并自由输入内容。
2. 系统识别说话、行动、观察、威胁、行贿、撒谎等意图。
3. 规则引擎读取场景、时间、关系、证据和 NPC 知识投影。
4. AI 生成结构化候选回复。
5. 规则引擎验证候选结果并写入合法状态变化。
6. 页面显示 NPC 回答、可观察动作和实际后果。

**边界**：AI 不得直接修改气血、银两、物品、地图、关系、事件或死亡状态。

### BS-05：场景调查

1. 玩家自由描述调查行为，例如检查行囊、观察伤口或查看告示。
2. 系统判断场景是否存在目标、玩家能力是否足够、是否耗时及是否会被旁人注意。
3. 成功时获得分层线索；失败时只显示玩家能够观察到的内容。
4. 调查可能推进时间、增加疲劳、暴露意图或触发 NPC 反应。

### BS-06：地图与旅行

1. 首页仅显示“地图”入口，不直接列出所有地点。
2. 地图只显示主角已经确认的地点名称。
3. 玩家选择地点后，弹窗显示目的地、基础耗时、天气、伤势和轻功修正。
4. 玩家确认后才移动并推进世界时间。
5. 未知地点无法直接输入名称传送。

### BS-07：住宿、治疗与生存状态

- 疲劳会降低观察、交涉和战斗表现。
- 轻伤长时间不处理会损失气血并可能恶化。
- 客栈休息消耗银两、恢复疲劳、推进世界时间并留下住宿记录。
- 医馆治疗消耗银两或人情，恢复伤势，但可能要求说明来源。
- NPC 对伤势的判断必须以实际检查为前提。第二日无名尸调查先提供尸体的可知情况；只有沈砚秋已经检查过主角伤口，才出现“两处伤口比对”并产出同源线索。
- 玩家可以尝试露宿、自行包扎或寻求其他帮助，并承担相应风险。

### BS-08：固定世界事件

1. 世界事件依据游戏内时间触发，不依赖玩家接取任务。
2. 未被玩家观察到的事件只写入隐藏世界状态，不自动显示在情报栏。
3. 玩家通过目击、传闻、证据或相关 NPC 才能获知事件。
4. 事件“发生”固定，事件“结果”根据此前状态计算。
5. 固定大事件之间可发生短小场景事件，例如换岗、巡查、店伙传话、伤者上门或可疑货车经过，用于表现世界在运转；这些事件同样受时间、地点和知识边界约束。
6. 每项决定核心结论的重要信息至少提供三条可替代获取路径；NPC 死亡、拒绝合作或玩家错过一次现场时，剧情不能永久断线。

### BS-09：危险言论与死亡

1. 玩家可以威胁、羞辱、冒充或泄露危险线索。
2. NPC 根据身份、性格、战力、现场人数和利益判断反应。
3. 后果可包括怀疑、涨价、拒绝服务、搜查、跟踪、拘捕、伏击和战斗。
4. 死亡必须由可追溯风险产生，不能只因模型随机生成。
5. 默认死亡后可读取已有存档；永久死亡模式不属于首期范围。

### BS-10：保存、读取与恢复

- 提供一个独立自动存档，以及最多 20 个由玩家管理的手动存档；自动存档不占用手动存档数量。
- 手动保存时可新建存档或选择已有存档覆盖；新建存档允许使用默认名称，也允许玩家自定义名称。
- 存档列表至少显示存档名称、主角名称、游戏内日期与时刻、所在地点、现实保存时间和游戏版本，并默认按最近保存时间排序。
- 玩家可以从列表中明确选择任一存档读取，不强制只能读取最近存档；“继续游戏”读取最近一次有效保存的自动或手动存档。
- 手动存档达到 20 个时，不得静默覆盖；玩家必须选择覆盖或删除一个已有手动存档，也可以取消本次保存。
- 覆盖和删除存档前必须弹窗确认。读档将丢失尚未保存的当前进度时，应提供“先保存当前进度”“不保存并读取”“取消”三种选择。
- 移动、休息、治疗、重大线索和世界事件结算后自动存档。
- 写入不同的有效自动存档前，保留上一个有效自动存档及其原保存时间；重复保存同一状态不挤掉上一进度备份。损坏主档不得覆盖有效备份。
- 存档损坏时提示并允许尝试读取备份。
- 存档包含世界状态，但界面只展示玩家已知投影。
- 当前开发基线从 v5 开始，既有 v1-v4 浏览器存档不迁移，按不兼容存档处理。

### BS-11：AI 不可用时继续游戏

1. 网络断开、Key无效、超时或供应商失败。
2. 当前输入不写入结果状态，玩家可以重试或切换有限对话模式。
3. 有限模式隐藏自由输入框，只显示由本地规则依据当前地点、已知信息、人物状态和对话阶段生成的情境选项。
4. 情境选项支持问路、住宿、治疗、交易、基础调查和事件推进，但不得提前泄露未知地点、NPC身份、隐藏线索或推荐唯一正确路线。
5. AI 恢复后可继续当前存档，并重新启用自由输入。

### BS-12：递进式对话显示与历史

1. 主界面一次只显示一句旁白、玩家发言或 NPC 回答。
2. 若一次交互产生多句内容，玩家点击“继续”逐句阅读；读到最新一句后才出现下一轮可选回应。
3. “对话历史”图标打开完整记录面板，面板只读，不改变游戏状态。
4. 不提供“回看上一句”或撤销入口；需要回顾内容时统一使用完整对话历史。
5. 读档或从地图返回时默认定位到最新一句，避免重复强制播放旧内容。
6. 已经确认姓名的 NPC 不再提供重复询问姓名选项；已经完成的一次性调查节点应消失或递进为新的追问。
7. 多 NPC 场景的抵达旁白不得与当前选中对象错位；人物外观由人物区随选择展示。

### BS-13：NPC 关系、记忆与话题锁定

1. NPC 关系不是一个单独的“好感度”数字，而由态度、信任、戒心、敌意和人情分别表达；同一行为可以同时提高信任并提高戒心。
2. 规则层至少记录：玩家报出的姓名与来历、是否提及“丁字十七”、是否展示伤口或残片、前后矛盾、承诺、欠债、帮助、背叛、某话题被询问和拒绝的次数及当次对话如何结束。
3. UI 不显示精确关系数值，只通过可观察的语气、称呼、动作和服务条件表达变化；洞察只能提高判断准确度，不能直接显示 NPC 秘密。
4. 有限模式中，一个话题明确遭拒后移除无意义的重复按钮；只有获得新证据、关系变化、时间推进或场景改变后才可重新开启。
5. 未来 AI 模式允许玩家继续追问，但无新依据的反复施压会降低态度、增加戒心，并可能让 NPC 涨价、撒谎、拒绝服务或结束对话。
6. 每名核心 NPC 具有不同的交谈结构：马三刀偏盘问与口供比对，苏晚棠偏交易与住客记录，沈砚秋偏诊断与证据追问，陆观澜偏试探、反问和半真半假的考校。
7. NPC 可以主动提问；一次谈话必须存在自然结束原因，例如公务、疲劳、戒心、时限或现场事件，而不是无限停留在同一选项池。

### BS-14：轻经济与早期成长

1. 正常开局银钱应足以承担一次普通治疗和两至三晚普通住宿，经济只形成轻微取舍。
2. 银钱主要用于贿赂、额外情报、较好药物、训练和更安全的解决办法，不作为第一、二日基本生存的硬性门槛。
3. 银钱不足时保留人情债、一次性杂活、基础止血、廉价住宿或露宿等替代路线；挣钱机会是可选且每日有限，不能形成无限刷钱循环。
4. 第一、二日只提供能力使用记录、基础指点和训练机会，不直接授予高阶功法。陆观澜可提供基础剑理或步法点评，沈砚秋可提供基础包扎与辨伤学习。
5. 功法分为基础能力、招式、套路、内功、轻功和特殊技艺；获得秘籍不等于立即掌握，提升仍需理解、练习、时间及必要的师承或资源。

## 6. 核心游戏循环

```text
观察场景或人物
      ↓
自由输入说话/行动（AI 可用）
或选择情境行动（有限模式）
      ↓
规则验证与AI表达
      ↓
时间、状态、关系和知识发生变化
      ↓
世界事件继续推进
      ↓
玩家发现新的风险、地点和选择
```

循环不以“接受任务—完成任务—领取奖励”为主要结构。

## 7. 功能范围

### 7.1 P0：Demo 必须完成

- Windows 单机安装包或可独立运行的便携版本。
- 新游戏、继续游戏、存档管理、设置和退出。
- 六个现有地点与独立地图页面。
- 八名核心 NPC 的身份、目标、秘密、知识边界和关系状态。
- 八日固定事件时间轴。
- AI 可用时的自由输入对话与行动入口。
- OpenAI-compatible AI 供应商配置与连接测试。
- AI结构化输出、规则校验与失败回退。
- 角色能力、气血、内力、疲劳、伤势、中毒和银两。
- 初步养成：能力使用记录、训练和有限提升。
- 文本战斗、逃跑、投降、死亡和读档。
- 线索、物品、地图知识、NPC认知和玩家主张记录。
- 一个独立自动存档、最多 20 个可命名手动存档、自由选档读取和备份恢复。
- AI不可用时的有限规则对话。
- 单句递进对话框与只读完整对话历史。
- 第一、二日扩展对话：每轮 3—5 个克制的情境选项、主动提问、话题锁定和跨日回声。
- NPC 结构化对话记忆，以及态度、信任、戒心、敌意和人情的规则结算。
- 轻量经济兜底与不可重复刷取的早期训练机会。
- 开发文字可配置隐藏，发行构建默认关闭。

### 7.2 P1：Demo 验证后

- Ollama 本地模型连接。
- 更多角色出身与随机开局差异。
- 完整武学招式、装备、药品与训练体系。
- 更多地点、普通 NPC 和随机事件。
- 存档导入导出。
- 字号、对比度、打字速度和无障碍设置。
- 更细致的长期记忆摘要和谣言传播。
- Windows 自动更新或版本检查。

### 7.3 明确不做

- 多人联机、PVP、排行榜、公会和玩家交易。
- 用户账号、云存档、云成就和跨设备同步。
- 开发者统一代理 API 或承担测试玩家的模型费用。
- 手机、macOS、Linux和主机版本。
- 3D场景、即时动作战斗、大量角色动画和全程语音。
- AI自动创造永久世界设定、核心 NPC 或未审核大事件。
- Steam创意工坊、模组平台和商业支付。
- 首期完全离线的无限自由对话。

## 8. 游戏规则边界

### 8.1 三类信息必须分离

1. **世界事实**：真实背景、NPC秘密、事件结果，由规则引擎保存。
2. **玩家已知**：主角通过观察、对话和证据确认的信息。
3. **玩家主张**：玩家声称的身份、经历和解释，可能是真话、误解或谎言。

玩家输入“我是朝廷密探”只会生成一条主张。NPC是否相信由证据、口才、关系和风险决定，不能直接把身份改成朝廷密探。

### 8.2 NPC 知识边界

- 每名 NPC 只能接收自己的已知事实、亲历事件和对玩家的记忆。
- 不向模型发送该 NPC 不可能知道的秘密。
- NPC可以撒谎、隐瞒或误判，但必须有动机。
- NPC身份在主角合理确认前只显示观察标签。
- 传闻不能自动与眼前人物对应，必须存在合理识别条件。

### 8.3 AI 与规则引擎的职责

| 能力 | AI | 规则引擎 |
|---|---|---|
| 理解自由输入 | 主责 | 校验 |
| 生成人物语言 | 主责 | 审核边界 |
| 生成观察性叙述 | 候选 | 决定可见内容 |
| 修改数值 | 禁止 | 唯一负责 |
| 发放或移除物品 | 禁止 | 唯一负责 |
| 解锁地点和线索 | 只能提出候选 | 唯一负责 |
| 决定战斗和死亡 | 禁止 | 唯一负责 |
| 触发世界事件 | 禁止 | 唯一负责 |
| 修改人物秘密 | 禁止 | 只允许设计数据或正式迁移 |

## 9. AI 对话需求

### 9.1 输入上下文

每次请求仅包含：

- 当前地点及玩家可观察描述；
- 当前世界时间和天气；
- 玩家状态的必要部分；
- 当前 NPC 的身份设定、性格、目标、语言风格和知识投影；
- 当前 NPC 对玩家的态度与历史摘要；
- 最近若干轮相关对话；
- 当前输入；
- 允许返回的结构化字段说明。

不得发送与当前 NPC 无关的完整世界秘密。

### 9.2 输出格式

AI 必须返回可校验的结构化数据，至少包含：

- 识别出的主要意图；
- NPC回答候选；
- 观察叙述候选；
- 建议的时间成本；
- 建议的态度变化；
- 建议暴露的知识标识；
- 风险标签；
- 是否需要规则引擎进行战斗、交易或技能检定。

解析失败、字段越权或引用未知标识时，结果必须被拒绝，不得部分写入状态。

### 9.3 记忆策略

- 最近对话保留原文，数量受上下文预算限制。
- 长期记忆存为结构化事实和短摘要。
- 谎言记录“谁说了什么、谁相信到何种程度”。
- 长期记忆以“人物—事件—话题”为索引，保留身份主张、证物展示、承诺、欠债、帮助、告密、背叛、拒绝及前后矛盾。
- 重复询问、冒犯、欠债、救命、告密和背叛必须形成长期影响；普通闲聊和重复选择不能反复增加关系或能力。
- 有限模式与 AI 模式共用同一份记忆状态和关系结算规则，区别只在意图入口与文字表达。
- AI生成文本不是永久事实，只有规则引擎确认的结果才能进入长期记忆。

### 9.4 成本控制

- 设置单次最大输入与输出长度。
- 只发送相关 NPC 和相关线索，不发送全量世界数据。
- 长对话自动摘要，但保留关键承诺、谎言和冲突。
- 设置页显示当前供应商、模型与是否启用 AI，不在 Demo 中计算或代付费用。

## 10. 角色养成与风险系统

### 10.1 基础能力

- 武学：近身交手、兵器运用和招式理解。
- 轻功：移动、闪避、追踪和逃跑。
- 洞察：发现线索、识破谎言和判断细节。
- 口才：说服、套话、伪装和讨价还价。
- 警觉：发现埋伏、跟踪和危险意图。
- 医术：判断伤毒、自救和识别药物。

### 10.2 首期成长方式

- 有意义且有风险的能力使用可积累隐藏熟练度；是否成功影响收益，但不能让失败路线完全没有学习价值。
- 训练、请教或阅读对应资料可提升能力。
- 单次普通闲聊不能反复刷取熟练度。
- 提升需要时间、银两、师承或物品中的至少一种成本。
- Demo内能力上限较低，避免数值膨胀。
- 成长对象包括基础能力、招式、套路、内功、轻功和特殊技艺；秘籍只是学习条件，不等于即时掌握。
- 六十日成长节奏为：第 1—2 日建立能力基线并埋下师承机会；第 3—8 日可获得首个基础技艺或招式；第 9—20 日形成方向；第 21—40 日专精；第 41—55 日允许一次重要突破；第 56—60 日主要检验积累成果。

### 10.3 轻量经济规则

- 开局资源应覆盖一次普通治疗和两至三晚普通住宿，不以饥饿或每日打工作为主要循环。
- 银钱用于换取便利、情报、药物、训练和风险转移，资源不足时主要减少优选方案，不直接关闭所有可玩路径。
- 允许欠诊金、一次性杂活、低质量免费处理或承担露宿风险；这些替代方案必须留下人情、时间、记录或安全代价。
- 每项挣钱行为设置时间成本、每日次数或剧情条件；重复对话、反复进出场景不得刷新报酬。

### 10.4 风险与后果

- 高疲劳降低检定表现。
- 轻伤不处理会恶化，重伤显著增加移动和战斗风险。
- 中毒依据类型随时间结算。
- NPC敌意达到阈值后可拒绝、跟踪、拘捕或伏击。
- 危险行动在执行前不显示精确成功率，但应通过场景和人物反应给出可理解警告。

## 11. 单机桌面架构

### 11.1 目标结构

- 桌面外壳：Tauri。
- 页面层：Vite + React SPA。
- 游戏规则：纯 TypeScript 模块，保持可单元测试。
- 本地能力：通过 Tauri command 调用文件、数据库和安全存储。
- 存档：本地 SQLite；导出备份可使用版本化 JSON。
- API Key：操作系统安全存储，不进入 SQLite 普通表、日志或导出存档。
- AI供应商：统一接口，首期实现 OpenAI-compatible HTTP；后续实现 Ollama。

### 11.2 从现有项目迁移

1. 冻结当前 Vinext 网页版为可回退基线。
2. 将游戏规则、类型、世界数据和测试迁入独立核心目录。
3. 将两个现有页面改为 React Router 或等价的客户端路由。
4. 用桌面存档仓库替换 `localStorage`，保留版本迁移。
5. 接入 Tauri 外壳、窗口、文件目录和安全存储。
6. 接入 AI设置与供应商适配层。
7. 验证 Windows 安装、升级、存读档和异常恢复。
8. 桌面版稳定后再移除不再使用的 Sites/Vinext 托管配置。

### 11.3 迁移原则

- 不在同一步同时重写规则引擎和桌面外壳。
- 现有剧情文档、世界数据和规则测试必须保留。
- 每次存档结构变化都必须提高版本号。当前开发期 v1-v3 存档允许直接失效；进入对外测试基线后再要求提供迁移函数或明确的不兼容提示。
- 在桌面存档稳定前保留网页版作为对照版本。

## 12. 本地数据设计

### 12.1 设置数据

- 音量、字号、打字速度等普通偏好。
- AI启用状态、服务地址、模型名称、超时和重试次数。
- API Key仅保存安全存储引用，不保存明文副本。

### 12.2 存档数据

- 存档唯一标识、存档类型、玩家自定义名称、创建时间、最后保存时间和游戏版本。
- 用于列表预览的主角名称、游戏内日期与时刻、所在地点；预览字段不得包含玩家未知的隐藏世界信息。
- 玩家能力、状态、物品、银两、声望和养成进度。
- 世界时间、已触发事件、地点状态和势力状态。
- NPC状态、关系、知识、记忆摘要和对玩家的判断。
- 玩家已知线索、未确认传闻和玩家主张。
- 最近对话与长期摘要。
- 随机种子或必要的可复现结果。

### 12.3 不进入存档的数据

- API Key及其他凭证。
- 完整请求和响应调试日志。
- 操作系统用户名、设备信息和无关文件路径。
- 未经玩家允许的遥测数据。

## 13. 安全与隐私

- Demo不收集账号、实名和支付信息。
- 默认不上传存档、对话历史或崩溃文件。
- 调用AI前明确提示会向玩家选择的供应商发送必要文本。
- API Key在界面中遮罩显示，日志必须脱敏。
- 自由输入属于不可信数据，不能作为系统指令、文件路径或命令执行。
- 模型输出必须经过 JSON Schema 和规则白名单验证。
- 桌面端不得向模型开放任意文件读取、终端或系统命令能力。
- 存档文件只允许在游戏数据目录及玩家明确选择的导入导出路径中读写。

## 14. 界面需求

### 14.1 主菜单

- 新游戏。
- 继续游戏。
- 读取存档。
- 设置。
- 退出。

“继续游戏”直接载入最近一次有效保存；“读取存档”进入完整存档列表，由玩家自行选择。若最近存档损坏，应跳过损坏项并提示玩家选择其他存档或自动存档备份。

### 14.2 存档管理界面

- 自动存档与手动存档分区显示，明确标注自动存档不占 20 个手动名额。
- 手动存档列表显示名称、主角、游戏内日期与时刻、地点、现实保存时间和版本。
- 提供“读取、新建、覆盖、重命名、删除”操作；当前选中的目标必须清晰可见。
- 达到 20 个手动存档时禁用直接新建，并引导玩家选择覆盖或删除，不替玩家自动决定。
- 覆盖、删除和放弃未保存进度后读档均需确认；取消操作后保持当前游戏状态不变。

### 14.3 游戏主界面

- 当前场景与可观察描述。
- 当前可见人物，未知人物不得显示真名和身份。
- 对话与行动记录。
- 自由输入框与自动判断、说话、行动模式。
- 玩家可知状态：气血、内力、疲劳、伤势、中毒、银两。
- 已确认线索、随身物和地点。
- 地图、存档、读档和设置入口。

### 14.4 设置界面

- AI启用开关。
- 供应商类型、服务地址、模型名称和 API Key。
- 测试连接。
- 超时和有限模式选项。
- 字号、文字显示速度和音量占位。
- 开发信息显示开关；发行构建默认关闭。

### 14.5 错误提示

错误信息必须说明用户下一步可以做什么，例如：

- “API Key无效，请检查后重新测试。”
- “模型响应超时，本次输入尚未写入游戏状态。”
- “已切换到有限对话模式，存档与世界事件不受影响。”
- “自动存档损坏，是否尝试读取上一份备份？”

## 15. 非功能需求

### 15.1 兼容性

- 首期支持 Windows 10/11 x64。
- 不要求玩家预装 Node.js、Rust、Python或开发工具。
- 不配置本地模型时，不对显卡提出专门要求。

### 15.2 性能

- 不含AI等待时，页面操作应在普通电脑上即时响应。
- 存档写入不得阻塞主界面超过可感知时间。
- AI请求允许取消；超时默认不超过30秒，可在设置中调整。
- 长对话不会无限增长内存或请求上下文。

### 15.3 稳定性

- 关键状态变更采用先校验、后一次性写入。
- AI失败不得产生半次交易、半次移动或重复扣款。
- 浏览器版将内容、名称与保存时间封装在同一条记录中原子写入，并另保留有效自动备份；Windows SQLite 版使用事务更新主档与备份，不使用分离的非原子元数据写入。
- 损坏或不兼容手动档仍占用名额并可见，必须经确认覆盖或删除，不得当成空槽静默替换。备份预览使用备份自身的时间与状态。
- 所有存档读写在单个运行实例内串行执行；写入失败不阻断下一次重试，页面显示失败，不虚报保存成功。当前不承诺多个浏览器标签页同时写同一存档的冲突合并。
- “先保存再读档”必须先捕获所选目标，避免当前进度覆盖目标自动档后读错档；取消或读取失败不更换当前游戏状态。
- 本轮验收使用规则层、存档仓库及共用操作流程的自动化模拟，不要求真实鼠标点击；Tauri 命令契约模拟不等同于 Windows 原生 SQLite 集成实测。
- 崩溃后最多丢失上一个自动存档点之后的进度。

### 15.4 可测试性

- 规则引擎不依赖桌面窗口和真实AI即可运行单元测试。
- AI适配器支持固定响应和失败模拟。
- 时间事件可通过测试时钟推进。
- 关键剧情结果使用稳定标识，不依赖模型原文判断。

## 16. 验收标准

### AC-01：独立运行

- 在未安装开发工具的 Windows 测试机上能够启动游戏。
- 无账号即可创建角色和存档。

### AC-02：AI配置

- 能保存非敏感模型配置并安全保存 API Key。
- 能区分连接成功、鉴权失败、超时和模型不存在。
- Key不会出现在存档和普通日志中。

### AC-03：自由输入

- “我要投宿”只解锁住宿相关信息。
- “我要找大夫”只解锁求医相关信息。
- 普通报来由不会被强行塞入两个地点提示。
- 玩家虚构身份不会直接改变真实背景。

### AC-04：知识边界

- 未确认人物只显示观察标签。
- NPC不回答其 `unknownFacts` 中的信息。
- 未观察到的世界事件不自动出现在已知情报中。

### AC-05：规则权威

- 模型要求发放不存在的物品时，规则引擎拒绝写入。
- 模型返回非法地点、数值或事件标识时，本次结果失败且状态不变。
- 战斗、死亡、交易和旅行结果可由确定性测试验证。

### AC-06：存档

- 自动存档与最多 20 个手动存档相互独立，自动存档不计入手动数量。
- 玩家可以新建、命名、重命名、覆盖、删除并从列表中任选一个手动存档读取。
- 手动存档未满 20 个时可以直接新建；已有 20 个时，再次新建必须要求玩家覆盖、删除或取消，不能静默替换。
- “继续游戏”能够读取最近一次有效保存；“读取存档”不会擅自改为读取最新存档。
- 存档列表正确显示主角、游戏内日期与时刻、地点和现实保存时间，且不泄露隐藏世界信息。
- 当前进度存在未保存变化时读档，必须允许先保存、放弃变化或取消。
- 覆盖或删除确认前不改变任何存档；取消后保持存档列表和当前游戏状态不变。
- 重启游戏后状态一致。
- 损坏主存档时可以读取备份。
- 旧版本存档有明确迁移或不兼容提示。

### AC-07：AI故障

- 断网时可以继续移动、调查、休息、治疗和存读档。
- AI失败不会消耗时间、银两或物品，除非规则操作已在本地明确完成。
- 恢复连接后无需新建存档。

### AC-08：八日世界

- 八个固定事件按照游戏时间依次进入触发状态。
- 玩家不参与时事件仍然发生。
- 至少县令遇刺、掌门死讯和封城具有两种以上可验证结果。

### AC-09：第一、二日对话与关系

- 第一、二日单条正常路线包含 8—12 次会改变信息、关系、风险、资源或后续选项的有效决策，目标体验时长为 40—60 分钟。
- 每轮通常显示 3—5 个与当前情境有关的选项，并保留沉默、观察、拒绝或暂不行动中的至少一种合理选择。
- NPC 拒绝透露姓名或情报后，有限模式不继续显示同义追问；新证据、关系、时间或场景未改变时，重复尝试不得获得新信息或收益。
- 第一日的口供、住宿登记、伤口检查、残片处置和“丁字十七”暴露状态，至少有一项能在第二日产生可观察回声。
- 两日结束可形成至少三类明显不同的有效状态，例如治伤并获信、隐瞒追查、假名低调、向县衙交证、向漕帮交易或拘押复核；不存在唯一正确路线。

### AC-10：轻经济与早期成长

- 标准开局资源可支付一次普通治疗和两至三晚普通住宿。
- 银钱不足时仍至少存在一种可继续推进的替代方案，但要承担人情、时间、记录或风险代价。
- 同一闲聊、一次性工作或训练不能通过重复点击反复获得银钱、关系或熟练度。
- 第一、二日可以获得基础指点或成长记录，但不能直接掌握高阶功法；所有成长变化均由规则状态和测试验证。

## 18. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| AI答非所问或人物出戏 | 破坏沉浸 | 严格人物投影、结构化输出、规则回退和对话评测集 |
| 玩家通过提示注入要求模型泄密 | 剧透或破坏状态 | 输入视为不可信、NPC秘密不进入上下文、规则拒绝越权字段 |
| API成本或限流 | 测试中断 | 玩家自备Key、上下文摘要、请求上限和有限模式 |
| 存档版本频繁变化 | 丢失进度 | 当前开发期允许旧档失效；对外测试基线后使用版本号、迁移或明确不兼容提示、备份和固定测试样本 |
| 从Vinext迁移导致大量回归 | 延误 | 先抽离核心规则，保持测试通过，再更换页面外壳 |
| 自由度造成内容爆炸 | 无法完成 | 固定世界事实和事件，AI负责表达，不让AI无限创造系统内容 |
| 高死亡率显得随机 | 玩家挫败 | 风险必须有可观察信号，死亡由规则和累积后果产生 |
| 测试玩家不会配置API | 无法体验 | 首次设置向导、连接诊断和有限模式 |

## 19. Demo 完成定义

只有同时满足以下条件，才能称为“单机 Demo 完成”：

1. 玩家可以在一台干净 Windows 电脑上安装和启动。
2. 无AI时仍能完成开场、移动、调查、休息、治疗和存读档。
3. 配置有效 API Key 后可以自由与八名核心 NPC 对话。
4. AI不能绕过规则修改世界状态或泄露NPC未知秘密。
5. 八日事件能够推进，并至少有三项事件支持多种结果。
6. 角色具备可感知的养成、受伤、战斗和死亡流程。
7. 独立自动存档、最多 20 个手动存档、自由选档读取、覆盖删除确认和备份恢复通过测试。
8. 开发阶段提示默认隐藏，没有需要开发者解释才能操作的入口。
9. 核心规则、存档迁移、AI失败和剧情事件均有自动化测试。
10. 项目保留可继续扩充内容的数据结构，而不是把剧情写死在页面组件中。
11. 第一、二日对话不存在可无限重复的姓名询问、关系收益、熟练度或挣钱入口，且早期选择会在第二日留下可验证回声。

## 20. 后续决策点

### 第二阶段：第一、二日现有流程基线（2026-09-04）

- 已放行但未问路时，仍可向守门差役询问现有投宿/求医地点；客栈传闻提到回春堂后必须同步解锁地点。
- 只问差役姓名不能替代回答盘问。有限姓名话题明确被婉拒后，使用现有NPC已知记录保存拒答并移除按钮，换场景或读档不能刷新；通用话题重开和五维关系未在本轮开发。
- 搜查明确夺走残片时，物品必须离开玩家背包，但已知线索仍保留；未打开夹层时目前采用“粗查可能漏检”的既有确定性分支，不将未发现等同于不存在。拘押复核尚缺失，当前扣留是内容断点，不得宣称为完整可玩路线。

- 对话未读完不接受下一动作，页面异步交互期间不能切换NPC造成状态回写错位；地图预览/取消不推进时间，确认后存档成功才提交移动。
